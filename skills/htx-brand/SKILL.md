# HTX 品牌视觉规范

本 skill 定义 HTX 品牌视觉的设计语言，不限定具体尺寸与像素，所有数值按画布比例灵活推导。

> 普通无火宝品牌蓝社媒海报使用 `htx-social-poster`；普通火宝社媒海报使用 `htx-huobao-fast`。只有长图、复杂运营图、VIP、既有模板复刻或用户明确要求严格质检时，才使用本 Skill。

## 00 默认决策与火宝协作

用户未指定时，不追问可安全推导的设计参数：

- 普通活动、社群、邀请、奖励、上新海报：`brand-blue`
- 机构、VIP 或高级权益物料：`vip-gold`
- 社交活动海报：1080 × 1080
- Logo：100 × 100，固定右上角；普通白底使用 `assets/htx-logo-mark-100.svg`，柔和白蓝渐变使用 `assets/htx-logo-mark-inverse-100.svg`
- 版式：标题左对齐，火宝与主标题分区，辅助信息位于左下安全区

### 冻结快速流程

普通火宝正式海报默认使用 `scripts/compose-social-poster-fast.py` 直接在 PNG 上绘制文字和官方 Logo，不启动 Chrome。不得在计时任务中修改渲染器、创建新 HTML/CSS、提取前景、调整透明度、自动重绘或多次导出。

字体按整行选择：只要一行包含中文，该行全部使用 HarmonyOS Sans SC；纯英文行全部使用 Urbanist。禁止在同一行内按字符切换字体。默认 1080 × 1080 文字安全区上下左右均为 `80px`，可用宽度 `920px`；Logo 仍按品牌规范保持右上 `60px` 安全边距；火宝默认构图于右下并允许底部自然裁切。

**时间成本硬限制：**普通正式海报只允许一次场景生成、一次必要排版渲染和一次快速目检。机械 QA 只作为该次渲染的结果，不得触发自动改字号、改文本框、改换行、修改渲染器或再次导出。首次排版失败后立即停止并报告具体错误，等待用户决定；不得为了通过质检连续重跑。除非用户明确要求严格质检，否则不执行额外检查、调试渲染或验证页面。

1. 锁定用户原文。主标题目标 `140px`；固定排版器在绘制前允许于内置 `112–158px` 范围内一次性选择字号与 1–4 行换行，但不得改变原文。通过生图阶段预留足够的左侧空间，不允许人物压字。
2. 调用 `htx-huobao-fast` 一次，生成无文字、全幅蓝底火宝场景。人物裁切、短 T 恤比例、双手、道具、Logo 区和文案区必须在这一调用中完成。
3. 将已完成裁切的 1080 × 1080 场景直接传给轻量合成器。运行：

```bash
python scripts/compose-social-poster-fast.py \
  --scene /absolute/path/scene.png \
  --output /absolute/path/poster.png \
  --subtitle "副标题" \
  --title "主标题" \
  --date "日期或辅助信息"
```

4. 轻量合成器在绘制前一次性计算字号、换行与文字—角色碰撞：依据左侧品牌渐变采样识别火宝、双手和道具占位，逐行核对真实字体盒并保留安全距离。主标题必须以原始平衡换行为基准，优先做最小换行调整：只把发生碰撞行末尾所需的最少词组或字符移到下一行；禁止为了维持最大字号把整句机械拆成两字一行。完成最小调整后，再在内置字号范围内选择最大无碰撞方案。日期固定锚定于左下文字安全边距，不得自动上移；若与角色或道具碰撞，只能在 `24–32px` 内一次性选择最大无碰撞字号。若副标题、主标题或日期仍与角色/道具相交，必须在写出 PNG 前报错。检测不得触发第二次导出、自动生图或浏览器。命令失败时直接披露，不得在同一任务中修改代码后重跑。
5. 只查看最终 PNG 一次。通过快速目检即交付；失败时指出具体缺陷并停止。禁止在同一请求中自行修正后重跑。

查看冻结配置示例：

```bash
node scripts/run-fast-poster.mjs --print-example short
node scripts/run-fast-poster.mjs --print-example extended
```

制作普通火宝正式海报时，执行固定的精简流程：

1. 解析并锁定用户提供的标题、奖励、日期、链接、CTA 和其他业务事实；不增写、不润色。
2. 调用 `htx-huobao-fast` 的单场景流程，使用其内置官方参考图进行一次图像模型调用，输出无文字蓝底场景。
3. 生图阶段直接锁定版式：火宝位于右下，默认截取上半身。优先显示头部和上半身，让腰部或下躯干自然延伸出画布底边，腿脚不显示。裁切只能来自镜头构图或完整人物越出画布，禁止用抠图、蒙版、擦除、补蓝或局部消失模拟裁切。完整保留角、脸、双手、胸标、正常短 T 恤比例和主要道具，双手与道具不得触碰画布边缘；禁止拉长躯干或 T 恤。右上 Logo 安全区保持干净。
4. 不生成身份样张、透明交付图、棋盘格、绿幕、白底、探索变体或第二张场景。使用冻结执行器一次叠加官方 Logo、用户原文和辅助信息。
5. 主标题固定 140px。副标题 46–58px；日期、URL 或辅助信息位于左下安全区，不使用胶囊、按钮或底色。
6. 渲染后只做一次合并快速目检：火宝可辨识、单个蓝角、大眼、桃粉肤色、紧凑蓝色 T 恤、正常比例与白色胸标正确；上半身从画布底边自然退出，零腿脚可见；角、脸、双手和主要道具完整且不触碰画布边缘；没有蒙版擦除、残肢或局部消失；没有 AI 生成文字或水印；文案与人物保持分区，辅助信息位于左下安全区。
7. 机械 QA 与快速目检均通过后立即交付。快速目检失败时指出具体缺陷并停止，不自动再次调用图像模型；只有用户明确要求重试时再生一张。

不得为每张海报重新创建 HTML、CSS 或 Playwright 脚本。图像模型只生成无文字的蓝底火宝场景；文案和 Logo 必须由固定渲染器叠加。

仅当用户明确说“严格质检”“品牌母版”或“生产级修订”时，才进入更细的检查流程：仍只使用同一张官方参考图与固定身份锁，执行完整 L0 核对、场景门、裁切门、100% 清晰度检查和必要时最多一次定向重试。

底层渲染器配置示例仅用于复杂或非计时任务；普通正式海报必须使用上方冻结执行器：

```json
{
  "scene": "/absolute/path/huobao-blue-scene.png",
  "foreground": "/absolute/path/huobao-blue-scene-foreground.png",
  "sceneScale": 1.05,
  "sceneOffsetX": -50,
  "sceneOffsetY": -17,
  "output": "/absolute/path/poster.png",
  "eyebrow": "生日专属礼遇",
  "headline": "惊喜好礼等你来",
  "headlineLines": ["惊喜好礼", "等你来"],
  "headlineSize": 150,
  "cta": "立即领取"
}
```

`foreground`、`sceneScale`、`sceneOffsetX`、`sceneOffsetY`、`headlineSize` 和 `headlineLines` 为可选字段。`foreground` 只能与同尺寸的 `scene` 配对，用于人物压住部分文字的快速分层；场景缩放与位移必须同时应用于 `scene` 和 `foreground`，用来把腰部或下躯干贴到画布底边，并保持位图不被放大超过原始像素。用户明确指定字号时填写 `headlineSize`；需要避开角色时可用 `headlineLines` 控制换行，但数组按空格连接后必须与原标题逐字一致。未指定字号时由渲染器在安全区内自动放大。

运行：

```bash
node scripts/render-social-poster.mjs /absolute/path/config.json
```

渲染器的通过结果即为原文一致、官方 Logo、字体加载、文字溢出、大字号层级、画布尺寸、Logo 安全区和位图未放大的机械 QA 结果，不再重复人工核对或搭建第二套检查页面。默认视觉 QA 只执行一次上述快速目检。

用户只要求火宝素材时，交由 `htx-huobao-fast` 生成普通蓝底场景；不再提供透明素材、品牌母版或生产级身份核对流程。

### 正式海报质量门

- 默认机械门：用户原文逐字一致、官方 Logo 正确、内置字体加载、无文字溢出、文字与火宝/双手/道具无碰撞、主标题达到目标视觉占比、字号层级成立、安全区无覆盖、画布尺寸正确、场景位图未放大。全部由固定渲染器在写出 PNG 前一次完成。
- 默认快速视觉门：只检查可辨识火宝、单个蓝角、眼睛、肤色、紧凑蓝色 T 恤与胸标、上半身从底边自然退出、零腿脚可见、双手和道具完整且不触边、没有蒙版擦除或残肢、AI 文字/水印、明显模糊、左下时间位置和 80% 白色。使用前景分层时再检查全部可见人物区域保留、人物轻压文字但主标题仍可读。只检查一次，不制作 25% 辅助缩略图。
- 严格 L0 角色门：仅在用户明确要求严格质检时启用；逐项对照唯一官方参考图，检查头型、角、眼睛、眉毛、无鼻子结构、嘴、耳朵、肤色、比例、四肢、服装、胸标、材质与颜色。
- 严格透明素材与裁切门：仅在严格模式、独立素材或既有模板模式下启用；检查透明边缘、关节裁切、全尺寸与 25% 缩略图、双手、双脚和道具完整性。
- 默认模式任一快速门失败时停止并披露，不自动重绘。严格模式失败时才允许按明确失败原因最多定向重试一次。

## 01 主题系统

| 属性 | vip-gold（机构/VIP） | brand-blue（活动/品牌） |
|------|------|------|
| 品牌主色 | `#C9A84C` / 渐变 `#DEC48A → #F5ECD7` | `#0066FF` |
| 辅助色 | `#FFFFFF` | `#FFFFFF` |
| 字体 | Urbanist；中文回退 HarmonyOS Sans SC | Urbanist；中文回退 HarmonyOS Sans SC |
| 模块装饰 | 左侧竖线（无圆角） | 品牌蓝左侧竖线（无圆角） |
| 分割线 | `#E0D5C0` | `#E8E8E8` |

白色正文区颜色必须直接使用主题表中的规范值：正文与内容小标题为纯黑 `#000000`，品牌强调为 `#0066FF`，分割线为 `#E8E8E8`。禁止把黑色正文自行替换为深蓝、藏青、蓝灰或其他近似色；需要建立层级时只调整字号、字重和留白。

执行颜色修订时只允许修改颜色值；必须锁定原稿的 `font-weight`、字号、字族、字距、行高、透明度和抗锯齿覆盖，不得通过加粗、描边、扩大字形、不透明度归一化或重绘文字来强化新颜色。半透明文字改色时保留原始 alpha。

### 内置字体资产

所有输出必须使用 skill 自带字体，不得依赖操作系统是否安装字体：

- 英文和数字第一字体 Urbanist：

  - Medium 500：`assets/fonts/Urbanist-Medium.ttf`
  - Bold 700：`assets/fonts/Urbanist-Bold.ttf`
- 中文回退字体 HarmonyOS Sans SC：
  - Regular 400：`assets/fonts/HarmonyOS-Sans-SC-Regular.ttf`

  - Bold 700：`assets/fonts/HarmonyOS-Sans-SC-Bold.ttf`
- Urbanist 许可：`assets/fonts/OFL.txt`

Urbanist 不含中文字形。渲染器必须按字形回退：英文、数字和受支持的拉丁字符使用 Urbanist，中文使用 HarmonyOS Sans SC。不得添加 Noto，不得依赖系统字体回退。

非浏览器/Pango 渲染必须同时使用字体文件和字体内部名称：

- 拉丁第一字体：`Urbanist` / `Urbanist Medium` / `Urbanist Bold`
- 中文回退：`HarmonyOS Sans SC` / `HarmonyOS Sans SC Medium` / `HarmonyOS Sans SC Bold`

不得把自定义 CSS 别名作为 Pango 字体内部名称。导出前分别用拉丁字符和中文字符检查回退字体与字重；Bold 的笔画覆盖量必须明显高于 Regular，未通过时停止交付。

### 背景渐变规范

渐变方向统一为**从上到下，由深到浅**。

| 主题 | 方向 | 顶部（0%，深） | 底部（100%，浅） |
|------|------|------|------|
| brand-blue | 从上到下（180°） | `#0066FF` | `#2692FF` |
| vip-gold | 从上到下（180°） | `#DEC48A` | `#F5ECD7` |

**HTML 环境 CSS 写法（brand-blue）：**

```css
background: linear-gradient(180deg, #0066FF 0%, #2692FF 100%);
```

**HTML 环境 CSS 写法（vip-gold）：**

```css
background: linear-gradient(180deg, #DEC48A 0%, #F5ECD7 100%);
```

> ⚠️ **SVG 导出强制要求**：背景渐变必须使用 SVG 原生 `<linearGradient>` 实现，禁止使用 CSS `linear-gradient`。CSS 渐变在 SVG 导出后会失效，只能在 HTML 环境中显示。

**SVG 标准写法（brand-blue）：**

```svg
<defs>
  <linearGradient id="bg-gradient" x1="0%" y1="0%" x2="0%" y2="100%">
    <stop offset="0%" stop-color="#0066FF"/>
    <stop offset="100%" stop-color="#2692FF"/>
  </linearGradient>
</defs>
<rect width="100%" height="100%" fill="url(#bg-gradient)"/>
```

**SVG 标准写法（vip-gold）：**

```svg
<defs>
  <linearGradient id="bg-gradient" x1="0%" y1="0%" x2="0%" y2="100%">
    <stop offset="0%" stop-color="#DEC48A"/>
    <stop offset="100%" stop-color="#F5ECD7"/>
  </linearGradient>
</defs>
<rect width="100%" height="100%" fill="url(#bg-gradient)"/>
```

**色彩搭配原则**：品牌主色与辅助色自由组合，以下均为合法布局：
- 全主色背景（全蓝 / 全金）
- 全白背景
- 主色底 + 白色内容卡片
- 白色底 + 主色内容区块

**brand-blue 默认长图布局**：Hero 使用品牌蓝渐变，Hero 以下使用连续白色背景。默认不使用白色卡片、圆角容器或卡片内缩；仅在用户明确要求或内容必须独立分组时使用卡片。

**分区型社媒海报**：方图或竖版海报只要同时存在明确的标题组与内容组，也可以使用“品牌蓝 Hero + 连续白色正文”的硬分区结构，不因画布未达到长图比例而强制全蓝。全蓝版显得扁平时，优先用背景分区、留白和分割线建立层级，不自行添加几何纹理或装饰图形。

竖版分区型社媒海报以 Hero 为主要视觉、内容区为辅助承载。内容能够完整排下时，Hero 默认占画布高度的 `52–58%`，白色正文或信息卡占 `42–48%`；不得默认让白色内容区大于 Hero。只有规则、表格或正文密度确实无法容纳时，才允许增加内容区高度。

### 社媒海报版式选择

- 先按语义拆分标题组、核心利益点、内容组和辅助信息，再选择全蓝、蓝白分区或参考风格；不得让工作台输入字段直接决定固定模板与层级数量。
- 用户未提供或明确不要插画时，删除插画及其占位，不保留空白框、占位符或为了等待配图而产生的失衡留白。改用标题、核心数字、背景分区和有效留白建立视觉重心。
- 标题组与内容组同时存在时，优先使用蓝色 Hero + 白色正文或白色信息卡。白色区只承载必要内容，不为填满画面而扩大；内容较少时优先改为方图或扩大 Hero，不制造空洞的长画布。
- 白色信息卡需要增强切割感时，可左右全幅延伸至画布外，仅保留顶部圆角，底部使用直角并与画布底边相接。全幅背景和卡片边缘不受内容安全区约束，但卡片内部文字仍必须保留 `6–8%` 左右安全边距与合规底部留白。
- 圆角必须由矢量路径、CSS `border-radius` 或同尺寸遮罩生成；禁止缩放带圆角的位图、局部拉伸卡片或先做小图再放大，否则视为形变错误。
- 用户明确选择背景、提供相近参考，或全蓝背景明显缺乏层次时，读取 `references/background-library.md`，按用户指定、内容类型、文字安全区、画布比例和对比度顺序选择背景。只加载最终选中的单张资产；没有合格候选时回退到本节基础纯色、标准渐变或蓝白分区。
- 背景库资产视为用户批准的背景层，但不得因此改变正文颜色、字重、Logo 与安全边距规范。位图只允许等比覆盖和安全裁切，禁止拉伸、重绘、调色或为了适配文案破坏其主要视觉结构。

## 02 比例原则

### 字号
- Hero 主标题：先按画布宽度的 **5.5%** 计算，并执行 **68px 最小可读字号**
- Hero 副标题/时间：主标题的 40–45%，且不小于 **30px**
- 正文：主标题的 35–40%，且不小于 **30px**
- 内容小标题：正文的 140–150%，推荐约 **44px**；使用黑色文字
- 说明小字：正文的 80–90%，不受正文 30px 下限约束

**可读性优先原则**：比例负责适配不同画布和维持层级，最小字号负责实际阅读。当比例结果低于最小字号时，必须使用最小字号。正文下限适用于普通段落、列表、表格和主要页脚文案；注释、免责声明、来源和其他解释性小字除外。

> ⚠️ **出图前必须执行字号计算，不得跳过**：
> 1. 先用画布宽度 × 5.5% 算出主标题 px（例：1080px × 5.5% = 59px），再与 68px 下限比较，取较大值
> 2. 再按比例逐级推导副标题、正文、小标题和小字，并分别应用最小字号规则
> 3. 将计算结果和采用的下限以注释形式写在代码里，例如：
>    `/* 字号基准：画布1080px；主标题比例值59px，采用下限68px；正文比例值约25px，采用下限30px；小标题44px；解释性小字按需计算 */`
> 4. 禁止目测估算字号，禁止直接沿用上一张图的字号

### 工作台社媒海报文案适配

工作台社媒模板按可用区域和视觉占比适配文案，不设置固定字号上限。字号只是排版结果，不是输入约束。

2. 从上述起始字号开始，以 2–4px 为步长同步放大核心主标题及其关联层级。

### 短文案语义层级门

对 2–3 句短运营文案，必须先按语义标注为“顶部小标题 / 核心主标题 / CTA”，再写 HTML；不得按文案出现顺序默认它们同级。

- 泛化利益点、氛围句、限定语通常作为顶部小标题；奖励、核心数字或活动名称通常作为核心主标题。用户明确提供独立时间信息时，时间默认作为左下角辅助信息，不作为按钮。
- 1080 × 1080 以顶部小标题 42–48px、核心主标题 96–108px、CTA 30–36px 开始适配，然后按工作台规则继续放大；这些数值不是上限。
- 顶部小标题通常为核心主标题的 40%–50%，CTA 通常为核心主标题的 24%–32%；最终值由可用区域决定。
- 顶部小标题与核心主标题的字号比默认至少为 1:2；只有用户明确要求同级标题时才可缩小差距。
- 若相邻两句同时使用 700 且字号差小于 50%，判定为层级失败，必须重新分类或排版。
- 大小层级同时依靠字号、字重和垂直留白建立；不得仅靠按钮、颜色或换行制造假层级。

### 内容小标题装饰
- 长图、复杂运营图或多模块正文使用品牌蓝左侧竖线取代章节数字或罗马数字
- 竖线无圆角，高度约为小标题字号的 82%，宽度约为小标题字号的 14%，与文字垂直居中
- 小标题文字使用黑色或正文主色，不使用品牌蓝
- 竖线与标题文字的间距约为标题字号的 50–65%
- 普通方图或竖版单画布海报默认不使用小标题竖线；改用字号、字重、留白、背景分区或横向分割线建立标题与内容层级。只有用户明确要求，或内容已经形成三个及以上独立模块时才启用竖线。

### 字重
- **最重只用 `font-weight: 700`（bold），禁止使用 800、900 或 black**
- 层级建议：主标题 700，副标题 500，正文 400，强调数据 700
- 大标题靠字号拉开层级，不靠字重加粗

### 行高
- 表格单元格上下 padding 不小于正文字号的 1 倍
  - 即 `padding-top + padding-bottom ≥ 正文字号 × 2`
  - 例：正文 22px → 单元格上下 padding 各 ≥ 22px
- 行高随字号联动，禁止写死固定 px 后不跟字号调整

### 边距
- 两侧边距：画布宽度的 6–8%
- Hero 顶部留白：画布高度的 8–10%（长图自适应时约 80–100px）
- Hero 底部与顶部对称
- 内容区顶部留白：画布高度的 3–4%
- 内容区底部留白：画布高度的 1.5–2%，禁止贴边
- 模块间距：正文字号的 2–3 倍

### 单画布社媒海报安全边距

- 方图或竖版社媒海报采用全蓝、全金或全白单画布时，不套用长图正文区 `1.5–2%` 的底部留白；四边内容安全区统一按画布宽度的 `6–8%` 计算。
- 画布宽度为 1080px 时，普通文案、插画位和辅助信息默认左右、底部均保留 `80px`；任何情况下不得低于 `64px`。Logo 继续使用右上 `60px` 固定安全边距。
- 底部 slogan、日期、URL、免责声明及其他可见文字必须按真实字体盒检查：文字盒底边不得超过 `画布高度 - 80px`。禁止只检查 CSS `bottom` 数值。
- 右侧 Logo、插画、礼金、CTA 和正文必须按最终像素检查：除固定 Logo 外，最右可见像素不得超过 `画布宽度 - 80px`。
- 只有内容确实形成独立规则、步骤、表格或多模块正文时，才使用前述“内容区底部留白”规则；单画布海报即使高度超过宽度，仍优先执行本节。

### Hero 区高度
- Hero 区最小高度约为画布宽度的 44%，用于放置标题文字及右侧配图
- 标题文字在 Hero 区内垂直居中
- 右侧预留配图空间，文字区域右侧 padding 不小于画布宽度的 35%

## 03 禁止项

- **禁止对整张海报或火宝进行任何二次调色或曝光调整**：包括曝光、亮度、对比度、饱和度、自然饱和度、色相、白平衡、色温、色调、Gamma、曲线、色阶、滤镜、自动增强及类似处理。火宝生成结果的肤色、服装色、材质、高光、阴影、轮廓光和辉光均视为锁定视觉资产，不得为适配背景而修改。
- **禁止通过全图校色逼近品牌背景色**：brand-blue 背景必须直接使用规范渐变 `#0066FF → #2692FF`。背景不合规时只能替换独立背景层、恢复未经处理的合规源图，或重新生成合规场景；若无法在不改变火宝像素的前提下修正，必须停止并披露，不得交付近似色版本。
- **内容零发挥**：严格按用户提供内容排版，不增、不改、不润色，不添加任何未提供的文案、角标、评语、推荐标记
  - 出图前逐字核对：每一处文字必须能在原文档中找到出处，找不到的一律删除
  - 常见违规点：表头 badge（如"我们的平台"）、eyebrow 标签、Hero 副标注、装饰性小标签——这些均属自行添加，禁止出现
- **禁止自行添加任何背景装饰**：包括但不限于圆形、线条、光晕、几何图形、纹理、噪点等装饰元素，用户未提供的一律不加
- **#pg 背景色必须与整图主基调一致**，防止圆角处露出容器底色
- **底部免责声明区域禁止使用独立卡片背景色**：背景色与整图主基调一致，不单独设置色块
- **全图禁止出现斜体字**：包括免责声明、注释、说明小字，一律使用正体
- 除本规范明确规定的最小可读字号外，不写死像素尺寸，其余数值按比例推导
- 内容区底部禁止贴边
- 不使用阴影、霓虹色、深色大背景；渐变仅限背景层，禁止对内容卡片使用渐变
- 启用竖线装饰时必须无圆角；vip-gold 使用金色，brand-blue 使用品牌蓝
- 不添加页脚色条

## 05 输出格式规范

### 强制使用 HTML+CSS 方案

- **禁止用纯 SVG `<text>` 元素排版正文内容**。SVG 文本没有盒模型，字符宽度依赖字体渲染，跨平台、跨字体必然导致右侧溢出画布。
- 所有长图、海报、运营图一律使用 **HTML+CSS** 方案输出。
- 如场景必须使用 SVG（如导出矢量文件），正文段落须用 `<foreignObject>` 嵌套 HTML 处理自动换行，禁止用 `<text>` 排多字中文正文。

### 固定画布宽度必须配合 JS 缩放

画布写死设计宽度（如 1080px）时，必须用以下结构和 JS 让画布自适应预览容器，防止右侧被截：

**标准 HTML 结构：**

```html
<div id="wrapper" style="width:100%;overflow:hidden;">
  <div id="canvas" style="width:1080px;transform-origin:top left;">
    <!-- 内容 -->
  </div>
</div>
```

**必须附带的 JS：**

```javascript
function fitCanvas() {
  const canvas = document.getElementById('canvas');
  const wrapper = document.getElementById('wrapper');
  const scale = wrapper.offsetWidth / 1080;
  canvas.style.transform = `scale(${scale})`;
  canvas.style.transformOrigin = 'top left';
  wrapper.style.height = canvas.offsetHeight * scale + 'px';
}
fitCanvas();
window.addEventListener('resize', fitCanvas);
```

> ⚠️ 每张图输出前必须检查：是否有 `#wrapper` + `#canvas` 结构，是否附带上述 JS。缺少任一项会导致右侧裁切，属于严重输出错误。

### 非方形海报导出门

- `fitCanvas()` 只用于响应式预览，禁止把已经缩放的预览页或方形缩略图当作最终导出源。
- 1080×1280、1080×1350 等非方形海报必须使用与目标画布完全一致的导出 viewport 和裁切框，直接截取未缩放的 `#canvas` 边界。
- 禁止先导出方形缩略图，再通过居中裁切得到竖版成品；这种流程会吃掉底部或右侧安全区。渲染器不能保持目标宽高比时必须停止并披露，不得交付近似裁切版本。
- 最终 PNG 写出后必须读取真实像素尺寸，并再次核对四边可见内容：1080px 宽单画布海报的普通内容左、右、底部不得小于 `64px`，目标值为 `80px`；Logo 右边距必须为 `60px`。
- HTML 中存在合规 `padding`、`right` 或 `bottom` 不代表成品合规；最终 PNG 的像素边界检查才是导出门的判定依据。
